# 道生一 · 终极形态：桌面环境层（Ambient Agent）

> 日期：2026-10-14 ｜ 性质：**方向文档**（后续按本文落实；与 `VOICE_IO_RESEARCH.md`、`VOICE_VIDEO_INPUT_PLAN.md` 配套，不另起一套）
> 一句话：把「打开应用 → 打字 → 读回复」变成「**随时开口/给图 → agent 直接在桌面上把结果呈现出来**」——贾维斯式环境层。
> 但**不是去掉 UI，而是把 UI 从「一个应用」降级成「一组渲染器」**。

---

## 1. 贾维斯拆成 4 件事（我们的进度各不相同）

| 能力 | 含义 | 现状（2026-10-14 实测） |
| :--- | :--- | :--- |
| ① 输入无摩擦 | 随时开口/给图/给屏幕，不用找窗口 | 🟡 **雏形**：全局快捷键、托盘、系统通知已有；视觉三层栈（`image_inspect` → `vision_inspect` → 本地 VLM）已落地；**语音选型已定但未接线**（`VOICE_IO_RESEARCH.md`） |
| ② 呈现不固定 | **agent 自己决定**用卡片/图/动画/语音/页面 | � **骨架已落地**：展示 IR + 呈现决策 + 3 个出口（桌面浮层 HUD / 语音 `say` / 产物页）+ 降级矩阵（见 `DISPLAY_SURFACE.md`）；缺 `flow`/`animation` 渲染器与「钉回会话的卡片渲染」 |
| ③ 主动性与情境 | 知道你在干什么、该不该插话 | 🔴 基本为零（纯「你问我答」） |
| ④ 长期人格与记忆 | 认识你、记得你、跨设备 | 🟢 **最厚**：长期记忆 / 用户画像 / 跨会话摘要 / 工作流沉淀 |

**结论**：瓶颈在 ②（已从 🔴 提到 🟡：IR + 出口都落地了，差渲染器全谱），其次是 ③。
而 ④ 与内核（工具链/沙箱/验证凭据/审计）是我们的差异化护城河 —— 贾维斯的强项不是聊天，是**把事做完**。

---

## 2. 设计原则（含四条「反贾维斯」约束）

1. **双形态**：环境层（随手、低打扰）+ 工作台（全量、可审计、可回看）。**留痕不能丢** —— 审计、diff 确认、撤销、记忆是我们的核心资产，语音与浮层天生「阅后即焚」，所以**一切浮层结果都能钉回会话**，产物一律落 `~/Documents/道生一产物/`。
2. **UI = 渲染器集合 + 展示 IR**：模型产出**结构化展示意图**（IR），宿主决定落到哪个 surface。这样「agent 决定怎么展示」才有实现位置；也顺手治好现有老大难（模型手写 HTML 行列错位 / 大文件被截断 / 渲染器无数学引擎）。
3. **低打扰优先**：主动性分级（见 §7），默认不插话；常驻 HUD 必须有「静默/暂停」硬开关。
4. **本地优先**：音频/图像**不出设备**（已排除云端 ASR 与默认送云端的视觉档）。
5. **可降级**：同一个 IR 在不同 surface 上按能力降级渲染（HUD 小、页面大、语音只念摘要），不允许「换了个出口就出错」。

## 4. 展示 IR 草案（本方向的地基）

### 4.1 结构

```jsonc
{
  "kind": "card | metric | chart | flow | timeline | table | kv | callout | code | speech | page | animation",
  "title": "可选标题",
  "priority": "primary | secondary",     // primary 才会冒到 HUD/语音；其余只进工作台
  "life": "auto-5s | sticky | pin",      // 浮层生命周期（默认 auto-5s 自动淡出）
  "body": { /* 按 kind 定义 */ },
  "pin": true                            // 是否允许「钉回会话」
}
```

`body` 示例：

- `metric` → `{ "value": "1.2", "unit": "GB", "delta": "+8%" }`
- `chart` → `{ "type": "bar|line|pie", "series": [{ "label": "周一", "value": 3 }] }`
- `flow` → `{ "steps": [{ "id": "a", "label": "取数" }, …], "edges": [{ "from": "a", "to": "b", "label": "缓存未命中" }] }`
- `speech` → `{ "text": "三份邮件已回复" }`（只念这一句）
- `page` → `{ "markdown": "…" }`（交给现有 `answer_html` 渲染器）

### 4.2 与现有资产的关系（关键）

`answer_html` 的渲染器已经支持 `sheet / flow / sequence / tree / timeline / kv / callout / limits / annot` 八类组件 ——
**IR 就是它们的规范化上游**：HUD 与产物页共用同一份 IR，只是按 surface 能力裁剪。

| IR kind | HUD 浮层 | 托盘/通知 | 语音 | 产物页（answer_html） |
| :--- | :-: | :-: | :-: | :-: |
| card / callout | ✅ | ✅（截断） | ✅（念摘要） | ✅ |
| metric | ✅ | ✅ | ✅ | ✅ |
| chart | ✅（简化） | ➖ | ➖ | ✅ |
| flow / timeline / table / kv | ➖（降级成 card） | ➖ | ➖ | ✅ |
| speech | ➖ | ✅ | ✅ | ➖ |
| page | ➖ | ➖（给链接） | ➖ | ✅ |
| animation | ➖ | ➖ | ➖ | ✅（HTML/SVG 动画） |

### 4.3 为什么这层值得先做

现在「让模型直接写 HTML/SVG」的失败模式我们已经吃够：行列错位、大文件截断、无数学引擎、链接被当相对路径导航。
**把「想表达什么」与「怎么渲染」分开**，这些坑一次性变成宿主可控问题。

## 6. 输入层设计（复用既有两份文档的结论）

### 6.1 语音（选型已定，未接线）

- **引擎**：`sherpa-onnx` 官方 Rust crate（Silero VAD + 流式中文草稿 + 二次精修）——**本机唯一同时满足「中文强 + CPU 友好 + 官方 Intel Mac 预编译 + Rust API」的方案**。
- **前置**：本机 `index.crates.io` **不可达**，新增 Rust 依赖前必须**先配稀疏镜像**（`rsproxy.cn` / 清华 / 中科大，实测均可达）；该 crate 构建时会从 GitHub Releases 取预编译库（GitHub 可达 ✅）。
- **交互**：先做 **push-to-talk 半双工**（绕开回声消除 AEC 这个大坑）→ 再打断（barge-in）→ 最后唤醒词（sherpa-onnx KWS）。
- **三条必须照抄的 DSH 设计**：① **转写进草稿，不自动发送**（误识别不会触发一轮、省 token）② 准备是独立生命周期（下载/校验/加载 + 进度 + 失败分类 + 可取消）③ 识别并发 = 1 + 空闲释放（语音推理与 LLM 抢 CPU）。
- **TTS**：第一阶段直接 `say`（零依赖、离线、已有中文音色）→ 需要更自然再换本地模型。

### 6.2 图像 / 屏幕

`vision_inspect`（Vision 原生：分类/人脸/人体/姿势/动物/条码/显著区域）与 `image_inspect`（确定性像素/几何）**已落地**；
屏幕用 `screencapture`（本机在）取图 → 走同一栈。**本地 VLM 只用于「开放性描述」**（本机 10~40s/帧且会幻觉）。

### 6.3 视频

抽帧 → `VNGenerateImageFeaturePrint` 特征指纹去重 → 只留关键帧 → 走 §6.2 同一栈 → 汇总时间轴。
护栏：抽帧 ≤12 帧、总耗时预算、**明确声明「这是抽帧结论，不是连续观察」**（防模型编造「第 3 秒他笑了」）。

## 7. 主动性分级（先做什么、不做什么）

| 级别 | 行为 | 前置 |
| :--- | :--- | :--- |
| **L0 被动** | 你问我答（现状） | — |
| **L1 语境提示** | 只在你**刚提过**或**有时间性**的记忆上轻提示（如「昨天那份报告今天到期」） | 记忆/画像（已有） |
| **L2 建议** | 低打扰建议，可忽略、**不自动执行** | 预算护栏 + 静默开关 |
| **L3 代办** | 明确授权下自动跑（可回滚、可审计） | 权限矩阵 + 撤销（已有） |

**先做 L1**，L2/L3 必须在「静默开关 + 审计 + 预算」齐备后再开。

## 8. 分阶段路线（与既有两份文档对齐）

| 阶段 | 内容 | 成本 | 验收 |
| :--- | :--- | :--- | :--- |
| **A. 环境层骨架** | push-to-talk（全局热键）→ sherpa-onnx 转写 → **进草稿不自动发送**；TTS 播报 + 富通知 + **HUD 胶囊**（透明置顶、摘要 + 波形、点开进工作台） | 2~3 天 | 真机：按住热键说一句中文 → 草稿出现；答完自动念摘要；HUD 显示且不挡操作 |
| **B. 展示 IR + surface 注册表** | IR 定义 + 呈现决策 + 3 个渲染器（HUD 卡 / SVG 图表 / HTML 页）+ **钉回会话** | 3~5 天 | 同一份 IR 在 HUD/通知/语音/产物页都不出错；单测覆盖降级矩阵 |
| **C. 情境** | 屏幕上下文（`screencapture` → 视觉栈）、桌面摆放/拖拽、视频抽帧（`video_inspect`） | 1~2 周 | 截图问「这页有什么问题」能答；视频结论如实标注抽帧 |
| **D. 贾维斯感** | 唤醒词/免手（KWS）、全双工打断（需 AEC）、多设备延伸（IM 网关已有设计） | 远期 | — |

**每阶段的门禁**：`npm run ci:local` 八门禁 + 真机清单（录屏/截图留证）。

## 9. 硬约束与风险（均为实测事实）

- **本机是 Intel Mac（无可用 GPU）**：本地 ASR 只能小模型（走 INT8）；本地 VLM 10~40s/帧 → 视觉**永远确定性优先**。
- **权限**：麦克风 / 屏幕录制 / 辅助功能都要 macOS TCC 授权；打包版需在 `Info.plist` 写用途说明，升级后可能需重新授权。
- **透明窗口 + 点击穿透在 WKWebView 上有坑**（我们踩过 `mask` 失效）：HUD **已 spike 验证可用**（`docs/HUD_SPIKE.md`），但**必须有静默开关**（当前实现：不设 `DAOSHENGYI_HUD_SPIKE` 就永不创建窗口），且**不能抢焦点**（用 `orderFrontRegardless`，不是 `show()`）。
- **成本与延迟**：语音把 LLM 调用从「按任务」变成「按话轮」→ 必须加**本地预筛**（复用 `search-gate` / `danger-rules` 那套确定性门禁思路）+ 小模型先应答的分层。
- **隐私红线**：不做常驻录音、不做静默屏幕录制；音视频全本机处理。
- **依赖获取受限**：crates.io 不可达（需稀疏镜像）；npm registry 受限（故 HUD 优先用系统框架与已有依赖，不轻易引新包）。

## 10. 明确不做

- ❌ 做硬件（音箱/眼镜/别针）；
- ❌ always-on 录音 / 静默屏幕录制；
- ❌ 默认把音频或图像送云端；
- ❌ 做成「另一个 Siri」（闲聊不如把事做完——工具链、沙箱、验证凭据才是我们的护城河）。
