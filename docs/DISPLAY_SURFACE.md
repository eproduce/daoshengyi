# 展示层（Display Surface）：IR + 呈现决策 + 出口

> 日期：2026-10-15 ｜ 性质：**实现文档**（`docs/DESKTOP_AMBIENT_UI.md` §4/§8 的落地说明）
> 一句话：**模型说「想表达什么」（展示 IR），宿主决定「落到哪、怎么降级」（surface）**。
> 这样「agent 自己决定怎么展示」才有实现位置，也顺手治了老问题（模型手写 HTML 错位、长文塞进浮层）。

## 2. 数据流

```
模型 → present(kind/title/priority/life/speech/body)
        │
        ├─ parseDisplayIr   容错：未知 kind→card、超长截断、脏条目丢弃（**永不抛错**）
        ├─ planSurfaces     决策：静默/开关 → 该走哪些出口（附人话原因）
        │
        └─ invoke("surface_present", { ir, plan })
                 │
                 ├─ 再次门禁（读设置：静默 / HUD 开关 / 语音开关）——前端可能被绕过
                 ├─ HUD：ensure 窗口 → 定位 → 穿透 → **无焦点显示** → emit `surface://hud`
                 └─ 语音：`say`（经 run_wrapped_argv：沙箱 + 超时 + 审计）
                          │
                          └─ 返回人话总结（已显示/已念/未出声的原因）→ 进会话（留痕）
```

**为什么"推 + 拉"两条路都要**：事件是「推」，而 HUD 可能是**刚创建**的 webview —— 监听还没挂上，
推过去的就丢了。所以 Rust 同时把 IR 存进状态，HUD 挂载后再 `hud_last_ir` 拉一次。
少任何一条，都会出现「第一次不显示、第二次才显示」这种极难查的现象。

## 3. 呈现决策规则（宿主规则为主，模型只能建议）

| 条件 | 结果 | 原因 |
| :--- | :--- | :--- |
| 静默模式 | 只进会话 | 用户明确表达过"别打扰" |
| `priority = secondary` | 只进会话 | 模型**自己声明**次要；不拿"不确定"当不显示的理由 |
| `hudEnabled = false` | 不冒浮层 | 设置里关了 |
| `kind = page` | 额外走产物页 | 完整内容交给 `answer_html` 渲染 |
| 语音：`speechEnabled = false` | 不出声 | **默认关**：出声属于主动打扰（见 §3.2） |
| 语音：kind 不在可念集合 | 不出声 | 能看的别念，否则就是噪音（见 §3.2） |
| 语音：无可念文本 / 超 80 字 | 不选语音 / 只念第一句 | 宁可不念，也不念一句空话 |

### 3.0 语义：**调用即呈现**（一次 UX 纠正）

初版把「优先级」当成"冒不冒出来"的绊线：不标 `primary` 就只进会话，并加了一条
「主窗口在前台就不冒浮层」的门禁。真机用下来两个都错了：

- **模型没标 primary = 你不说它就不显示**。`present` 本来就是"我特意调一个工具"的动作，
  这个动作本身已经是最强的"值得一看"信号 —— 所以现在 **`priority` 默认 `primary`**，
  只有模型**显式**写 `secondary` 才降级进会话。
- **「前台就不冒」= 盯着屏幕时反而什么都看不到**。恰好是用户在守长任务的时候，
  最需要瞥一眼结果。而且浮层已保证**不抢焦点 + 点击穿透**，不会抢走操作；
  所以前台门禁整条删除（`SurfaceContext` 里不再有 `windowFocused`）。

一句话：**呈现由模型"调用"这个动作触发，打扰与否只在设置里关**（静默模式 / 开关）。

### 3.2 出声规则（`shouldSpeak`）

语音不是"有文本就念"。三条门禁全部满足才出声，否则**明确说明为什么没出声**：

| 门禁 | 规则 | 理由 |
| :--- | :--- | :--- |
| kind | 仅 `speech` / `metric` / `callout` / `card` | `table`/`code`/`page` 念出来没意义 |
| 文本 | 不为空（含 `speech` 字段或正文） | 不念空话 |
| 长度 | ≤ 80 字，否则**只念第一句** | 300 字的长文照播就是故意折磨人 |

每条决策都会带一句**人话原因**回给模型（`reasons`），工具结果里也会写清楚
「为什么没弹出来 / 为什么没出声」——不然用户只会看到"什么都没发生"。
### 3.1 收尾自动呈现（宿主兜底，不靠模型自觉）

光有 `present` 工具还不够：长任务结束时用户往往**已经走开**，而模型**不一定记得**调工具。
所以在本轮收尾处（与系统通知同一处）由宿主兜一次：`buildFinishIr` → `planSurfaces` → `surface_present`。

关键的是**预筛**（把“按话轮”变回“按任务”，与 `search-gate`/`danger-rules` 同思路）：

| 本轮情况 | 结果 | 理由 |
| :--- | :--- | :--- |
| 纯问答（没用工具） | `secondary` + `auto` → **只进会话** | 每轮对话都冒出来就是骚扰 |
| 用过工具 | `primary` + **`sticky`** | 真干活了值得看一眼；`auto` 几秒就淡，用户不在时等于白推 |
| 用户主动停止 | 不呈现 | 停止 ≠ 完成，不能误报 |

接线由**源码级契约测试**钉住（`tests/test-display-ir.test.ts`）：断言 `chat.ts` 里
`presentTurnFinished(...)` 与 `notifyTurnFinished(...)` 挂在同一处 —— 将来重构
“只搬走通知、漏掉呈现”时功能会静默消失，光靠单测抓不住。
## 4. 降级矩阵与不变量

各出口能**原生渲染**的 kind（不在表里的自动降级）：

| surface | 原生支持 |
| :--- | :--- |
| `hud` | card / metric / chart / kv / timeline / callout / code / speech |
| `speech` | speech / card / metric / callout |
| `session` | card / metric / chart / table / kv / timeline / callout / code / speech / page |
| `page` | page / card / code / table / kv / timeline / chart |

**不变量（有单测钉住）**：任意 `kind × surface`，`degradeForSurface` 之后的结果**必须是该出口原生支持的**。
否则就会出现「换个出口就渲染出错/一片空白」——那种问题只在真机上偶然暴露。

几个具体降级：`flow` 在会话里退化成时间轴、在浮层里退化成多行；`table` 落到浮层只留 4 行 +
「共 N 项」提示；`page` 落到浮层退化成正文文本；**`flow`/`animation` 目前没有渲染器，
所以在每个出口都降级** —— 矩阵只列真正能渲染的，不写"声明支持、实际空白"。

## 5. 开关与默认值

| 设置项 | 默认 | 说明 |
| :--- | :-: | :--- |
| 环境层：桌面浮层（`surfaceHud`） | **开** | 浮层已保证不抢焦点 + 点击穿透（不挡操作） |
| 环境层：语音播报（`surfaceSpeech`） | **关** | **出声属于主动打扰，必须显式开** |
| 环境层：语音音色（`surfaceSpeechVoice`） | 空 | **下拉选择**，选项来自系统 `say -v ?`（中文分一组排最前）；空 = 系统默认 |
| 环境层：静默模式（`surfaceSilent`） | 关 | 打开后只留会话，不出声、不冒层 |
| 环境层：收尾自动呈现（`surfaceAutoFinish`） | **开** | 任务结束时宿主兜一次结论（纯问答时不会冒） |
| 环境变量 `DAOSHENGYI_HUD_SPIKE` | 未设 | 仅 spike：不设则**永不创建** HUD 窗口（零成本） |

### 5.1 设置放在哪（一次 UX 纠正）

这四个开关原本塞在**「快捷键」页**里 —— 用户的原话是「设置为啥要放在快捷键那里」。
现在它们有自己的页签：**设置 → 界面与运行 → 通知与呈现**（内含「系统通知」+
「桌面浮层与语音」）。

理由：快捷键页回答的是"怎么**触发**"，而通知/浮层/语音回答的是"结果怎么**送达**"，
两件事混在一页，用户找开关时得先把快捷键列表读完。

### 5.2 音色列表与试听（不做硬编码）

音色**不写死在代码里**：不同机器装的语音包不同，写死必然过时。
- `list_say_voices()`：跑 `say -v ?`（同样经 `run_wrapped_argv`），解析出 `{name, locale, example}`
  —— 名字里有空格/全角括号（如 `Eddy (中文（中国大陆）)`）也不能切坏，解析器有单测;
  **示例句就是 `#` 之后那段**（系统自带），不用自己造例句。
- `preview_voice(voice, text)`：试听。点「试听」时先 `flushSettings()` 再念 —— 否则
  Rust 端读到的还是防抖里没落盘的旧音色。
- 真机实测：**179 个音色 / 19 个中文**，示例句正常（已加 `#[ignore]` live 测试钉住：
  `cargo test --offline --lib surface::tests::live_ -- --ignored --nocapture`）。
- ⚠️ **但“19 个中文”是个陷阱**（用户反馈：「除了 Tingting 其他音色都很奇怪」）：其中 **16 个是 Apple 的
  多语言趣味变体**（`Eddy (中文（中国大陆）)` / `Flo` / `Grandma` / `Rocko`…，名字带括号即变体），
  **真人中文只有 Tingting（zh_CN）/ Meijia（zh_TW）/ Sinji（zh_HK）三个**。
  而旧排序是「中文优先 + 名字字典序」→ **最怪的 Eddy 排在第一位**，用户点开第一个试听的就是它。
  ⇒ 修正：解析时标记 `variant`，**列表只列真人音色**（并注明隐藏了几个变体），排序把变体压到最后。
  **教训：列表排序也是产品决策。**

### 5.3 自定义音色（用自己的声音）

不内置克隆模型（本机 Intel 无 GPU，且 GB 级模型+P指不进这个仓库），而是给一条**命令模板**入口：

| 占位符 | 含义 |
| :--- | :--- |
| `{text}` | 待念文本（**单引号转义**后传入：文本来自模型，绝不能拼出命令） |
| `{out}` | 输出音频路径（含它 = 我们负责 `afplay` 播放，**能拿真实时长**、能打断） |
| `{ref}` | 参考音频（克隆类引擎要的那段参考音；设置页可选本地文件） |

- 不含 `{out}` = 引擎自己出声（我们不播、也不假装知道时长）；
- 试听与实际播报**走同一条路**（否则设置页的「试听」就是在骗人）；
- 引擎命令经 `run_shell_command_with`（代理注入 + 超时杀进程组），**不加沙箱**（用户自己的引擎要写缓存/输出，
  等同用户自己在终端跑）；文本侧仍然做了单引号转义，模型内容无法注入；
- 接 piper / GPT-SoVITS / CosyVoice / 自写脚本都行 —— **宿主不绑定实现**。
- 录制参考音频要麦克风（`cpal` + TCC），随语音输入阶段一起上（本机无 `afrecord` 类命令，已实测）。

> 设置界面的「试一下」按钮走的是**与模型调用同一条**路径（`surface_present`），
> 并把返回的总结原样显示 —— 这样"为什么没出声"在设置页就能看懂。
> 它调用了新增的 `flushSettings()`：`updateSettings` 是 300ms 防抖的，
> 改完设置**紧接着**调用依赖该设置的 Rust 命令会踩空（读到旧值）。

不调模型、不点鼠标就能验整条链路：

```bash

DAOSHENGYI_HUD_DEMO=1 npm run tauri dev          # 推一份固定展示内容

实测结果（2026-10-15）：

```
[surface] 演示结果:

## 7. 边界与不做

- **不做** `flow` / `animation` 渲染器（Phase B 的 SVG/时间轴视图）；
- **不做**「浮层局部可点」：当前是全局点击穿透，交互建议走「全局穿透 + 热键唤起交互态」；
- **不做** `backdrop-filter` 毛玻璃（实测在透明窗口上无效，见 `HUD_SPIKE.md` §4.4）；
  真毛玻璃要走原生 `windowEffects`，**待验证**；
- **不做**把 `present` 当正文替代品：浮层会淡出，**正文仍要写在回复里**（纪律已写进工具说明与提示词）。
