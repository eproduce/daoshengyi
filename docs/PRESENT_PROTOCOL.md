# 结果呈现统一协议（PRESENT protocol）v1

> 日期：2026-10-16 ｜ 性质：**协议规范 + 落地排期**
> 一句话：**任何产生「结果」的地方（模型工具 / 宿主收尾 / 定时任务 / 钩子 / 子代理 / 第三方工具）
> 都用同一份结构化意图说话，宿主按一张「出口能力表」决定它落到哪、怎么裁剪。**
> 配套实现文档：`docs/DISPLAY_SURFACE.md`（当前已落地的部分）。

---

## 0. 为什么需要「协议」（现状：三个孤岛）

展示层已经落地（IR + `planSurfaces` + `surface_present` + HUD/语音），但**送达路径仍是散的**：

| 结果 | 现在怎么送出去 | 问题 |
| :--- | :--- | :--- |
| 一轮收尾结论 | `buildFinishIr` → `surface_present`（HUD/语音） | 只覆盖「收尾」这一个来源 |
| 系统通知 | `notify_user(title, body, only_when_unfocused)` | **自己一套文本参数**，不认 IR；与浮层内容各写一遍 |
| 托盘态 | `tray_set_status`（前端节流推） | 又是第三种格式 |
| 定时任务 / 钩子 / 子代理 | 无（只能靠拼通知文本） | 「跑完了」只能嘴上说，不能把结果**放**出来 |
| 第三方（MCP / 技能） | 无 | 想"展示"只能让模型手写 HTML（我们已知的失败模式） |
| 产物页 / Quick Look | `answer_html` / `qlmanage` | 与上面完全没打通 |

后果有两个，都是真实踩过的：
1. **同一句结论要在三处各写一遍**（通知文本 / 浮层 IR / 正文），改一处漏两处；
2. **模型没有稳定手段表达"想给人看什么"**，退回手写 HTML → 行列错位、文件被截断、无数学引擎。

所以「统一协议」不是抽象洁癖，而是**把这些散点收成一条路**：

```
        ┌── 模型工具 present ──┐
        ├── 宿主收尾兜底 ──────┤
产生 ───┼── 定时任务 / 钩子 ───┼──►  呈现协议报文（IR）  ──►  决策路由  ──►  出口执行
        ├── 子代理 / 第三方 ───┤      （v/id/source/kind/…）   （纯函数）      （HUD/语音/通知/
        └── 前端 UI 事件 ──────┘                                            托盘/会话/产物页）
```

## 1. 协议的三层（缺一层就会退化成"又一套 UI 代码"）

| 层 | 回答 | 现状 | 本次要做的 |
| :--- | :--- | :--- | :--- |
| **① 意图层（IR）** | 「想表达什么」 | ✅ `src/utils/display-ir.ts`（12 kind + 容错解析 + `shouldSpeak`） | 补 `v`/`id`/`source`/`refs` 四个字段 |
| **② 能力层（出口注册表）** | 「每个出口能渲染什么、打扰多大」 | 🟡 JS 侧有 `SURFACE_KINDS` 常量表，Rust 侧 `plan()` 是**硬编码 if 分支** | 抽成**单一数据表**（前后端各一份镜像 + 契约测试对齐） |
| **③ 决策层（路由）** | 「这一条该走哪些出口」 | ✅ `planSurfaces(ir, ctx)`（纯函数，每条决策带人话原因） | 让 `source` 参与默认打扰级别；加**勿扰时段** |

三条纪律（延续既有做法）：
- **模型输出一律当不可信输入**：解析永不抛错，未知值降级 + 记 `issues`；
- **降级必须可测**：`degradeForSurface` 是纯函数，不变量 = 「任意 kind × 任意出口，降级后必须是该出口原生支持的」；
- **决策必须能解释**：每个"没显示 / 没出声 / 只进会话"都要带一句人话原因 —— 否则用户只看到"什么都没发生"。

## 2. 报文规范 v1

```jsonc
{
  "v": 1,                          // 协议版本：宿主按此选解析策略（未知版本仍按 v1 容错解析）
  "id": "ir_7f3a91",               // 幂等/去重/回执关联（HUD 可据此不重复弹同一条）
  "source": "model",               // model | host | schedule | hook | subagent | external | ui
  "kind": "callout",               // card|metric|chart|table|kv|timeline|callout|code|speech|page|flow|animation
  "title": "✅ 构建通过",
  "priority": "primary",           // primary(默认) | secondary(显式逃生口：只留痕)
  "life": "sticky",                // auto(默认，自动淡出) | sticky(留到下次) | pin(钉回会话)
  "speech": "构建通过，耗时 42 秒",  // 「要让用户听到的那一句」；念不念由宿主判（shouldSpeak）
  "body": { "text": "…", "tone": "success" },
  "refs": [                        // 新增：可跳回/可归属（通知点击、钉回会话、产物打开）
    { "kind": "file", "value": "~/op/daoshengyi/src/utils/display-ir.ts" },
    { "kind": "conversation", "value": "8f2ca196" }
  ]
}
```

| 字段 | 谁必填 | 说明 |
| :--- | :--- | :--- |
| `v` | 宿主补 | 模型不填时宿主按 1 处理；解析后**原样带回**回执，便于排查"旧客户端发了新报文" |
| `id` | 宿主补 | 模型可不填。用于 HUD 去重 + 回执关联；**不参与渲染** |
| `source` | 宿主补（模型调 `present` 时 = `model`） | 决定**默认打扰级别**（见 §4）。这是"定时任务的结果不该像用户当面问的结果那样闹"的实现位点 |
| `kind`/`title`/`priority`/`life`/`speech`/`body` | 模型/宿主 | 已落地，语义见 `DISPLAY_SURFACE.md` §3 |
| `refs` | 可选 | v1 只做两件事：**通知点击**与**钉回会话**跳转；不做文件预览等复杂动作 |

### 2.1 v1 **不做** `actions`（按钮）

浮层当前是**全局点击穿透**（不挡操作是它的核心优点），所以 HUD 上根本点不到按钮；
能点的出口（系统通知、托盘菜单、会话内卡片）**各自已有交互方式**。
在没有"可点出口"之前先加 `actions` 字段 = 定义一个没人能实现的契约。
等 §9 的 P-A4（通知/托盘收编）落地后再评估 **v1.1**。

## 3. 出口能力注册表（协议的第②层）

**单一数据表**，前后端各一份镜像（JS: `src/utils/display-ir.ts`；Rust: `src-tauri/src/surface.rs`），
由契约测试保证一致。

| surface | 原生支持 kind | 打扰度 | 默认 | 单条渲染预算 | 现存实现 |
| :--- | :--- | :-: | :-: | :--- | :--- |
| `session` | 全部（含 table/flow/page） | 无 | 开 | 全量 | 已有（工具结果 + 卡片渲染待做） |
| `hud` | card/metric/chart/kv/timeline/callout/code/speech | 低 | 开 | 380×132、正文 ≤400 字、chart ≤24 点 | ✅ 已落地 |
| `speech` | speech/card/metric/callout | 中 | **关** | ≤80 字，超长只念第一句 | ✅ 已落地 |
| `notify` | card/metric/callout/speech（标题+正文） | 低 | 关 | 标题 60 / 正文 140 | ✅ 已有 `notify_user`，**待收编** |
| `tray` | metric/card（≤8 字） | 极低 | 开 | 8 字 | ✅ 已有，**待收编** |
| `page` | page/card/code/table/kv/timeline/chart | 无 | 开（仅 kind=page/time） | 全量 | ✅ 已有 `answer_html` |
| `quicklook` | page（文件路径） | 无 | 关 | — | 🆕 一行命令（`qlmanage -p`），待做 |
| `im` | card/metric/callout/code/speech | 中 | 关 | 平台上限 | 🟡 设计已有（`IM_GATEWAY.md`），待做 |
| `animation` | — | — | — | — | ❌ 无渲染器（每个出口都降级，如实声明） |

**收编的动作**：`notify` / `tray` / `quicklook` 从"各自一套调用"改成"注册表里的一个出口"
—— 调用方只发 IR，不再自己拼文本。收益：`notifyOnFinish`、托盘摘要、IM 推送**共用同一份内容裁剪逻辑**。

## 4. 决策路由（谁决定落哪）

`planSurfaces(ir, ctx)` 已是纯函数，本次只**扩展上下文**，不改变"宿主规则优先"的立场：

| 输入 | 作用 |
| :--- | :--- |
| `ir.priority` | `secondary` → 只进 `session`（显式逃生口） |
| `ir.life` | `auto` 淡出 / `sticky` 留住 / `pin` 进会话卡片 |
| `ir.source`（新增） | 默认打扰级别：`model`/`host` 按原样；`schedule`/`subagent` **降一级**（无 `priority` 时按 `secondary`）；`hook` 同 `schedule` |
| `ctx.silent` | 用户在静默模式 → 只进 `session` |
| `ctx.hudEnabled` / `ctx.speechEnabled` | 出口总开关（**不设 `windowFocused`**：盯着屏幕时恰恰最需要瞥一眼，见 `DISPLAY_SURFACE.md` §3.0） |
| `ctx.quietHours`（新增） | **勿扰时段**（如 22:30–08:00）：非 `session` 出口一律不出声不冒层；**但 `session` 永远写**（不丢信息） |

**勿扰时段值得进 v1 的理由**：它是"低打扰"最便宜的实现（一个设置项 + 一段纯函数），
而语音播报/浮层一旦在深夜乱响，用户会直接关掉整个环境层 —— 那才是真的功能死掉。

| 来源 | 现状 | 接入方式 |
| :--- | :--- | :--- |
| 模型 | ✅ `present` 工具 | 已接入 |
| 宿主收尾 | ✅ `buildFinishIr` + `presentTurnFinished` | 已接入 |
| 子代理 | ❌ | 子代理结束 → `source: "subagent"`（默认降级，别让后台任务刷屏） |
| 定时任务 | ❌ | 跑完发 IR（`source: "schedule"`）；定时任务的"结果放哪"这才有了答案 |
| 生命周期钩子 | 🟡 hooks 有 `notify` 动作 | `notify` 动作改为发 IR（`source: "hook"`），保留旧的 title/body 兼容 |
| 前端 UI 事件 | ❌ | `source: "ui"`（下载完成、长任务进度） |
| **第三方工具（MCP / 技能）** | ❌ | **约定文本块**（见下） |

### 5.1 第三方怎么"发"一条呈现（协议真正的价值）

MCP 服务器 / 技能 / 用户自己的脚本没法调我们的 `invoke`，但**能返回文本**。约定：

```
<present>{"kind":"metric","title":"部署耗时","body":{"value":"42","unit":"s"}}</present>
```

宿主在**工具结果处理链**（`foldToolResult` 那一层附近）扫描该块 → 提取 → 同一套
`parseDisplayIr` → 同一套 `planSurfaces` → 同一套出口。
四条约束：
- 一段结果**最多提取 3 条**（防刷屏）；
- 提取后**从正文里删掉该块**（模型与用户都不该看到原始 JSON）；
- 解析失败**只记 `issues` 不报错**（第三方格式写错不该弄挂一轮）；
- 走**同一套沙箱/审计无关**的路径（纯数据，不执行任何命令）。

## 6. 协同呈现：同一条结果，多个出口**同时**出现

用户诉求原话：「**语音播报的同时，弹出对应的悬浮层**等等，多样化同步展现结果也是我想要的」。

现在多出口**能同时选**（`planSurfaces` 已返回数组），但**没有协同**：语音念 3 秒、浮层 6 秒后还在那儿；
浮层先淡出而语音还在念；用户按停只停了声音、浮层还亮着 —— 都是同一个缺口：**缺「呈现单元」这层编排**。

### 6.1 呈现单元（presentation group）

同一个 `id` 的所有出口执行 = **一个单元**，带时序意图：

```jsonc
{
  "id": "ir_7f3a91",
  "surfaces": ["session", "hud", "speech"],
  "sync": {
    "mode": "concurrent",                  // concurrent(默认一起上) | speech-led(先出声) | hud-led(先亮再念)
    "holdHudUntilSpeechEnds": true,         // auto 浮层的实际存活 = 朗读结束 + 1s 余量
    "onInterrupt": "all"                    // 任一出口被打断 → 同单元其它出口一起收（不留半句在念）
  }
}
```

### 6.2 内容分工：念的和看的**不是同一句话**

| 出口 | 取哪部分 | 效果 |
| :--- | :--- | :--- |
| `speech` | `ir.speech`（缺省才回落 `title`/首句） | 念**摘要**（≤ 80 字） |
| `hud` | `body`（数字/图表/多行细节） | 看**细节** |
| `session` | 全量留痕 | 事后可查 |

互补而不是复读。**去重规则**：若 `speech` 与浮层唯一可见文本完全相同，
且浮层没有额外信息（无 metric/chart/lines），则**只触发一个出口** —— 避免「念一遍又看一遍同一行字」。

### 6.3 并发与抢占（多条 IR 同时来）

- **语音永远串行**（两句话叠着念 = 谁也听不清）：队列上限 3，超出丢最旧并记 `issues`；
- **浮层同级抢占 = 最新胜**（旧内容直接换掉，不排队）；`life=sticky` 的浮层**不被抢占**；
- 抢占时对旧单元触发 `onInterrupt`（旧语音立刻停）。

### 6.4 同步精度分层（v1 / v1.1，均零新依赖）

| 能力 | v1（`say` 子进程，现状） | v1.1（`AVSpeechSynthesizer` Swift 侧车） |
| :--- | :--- | :--- |
| 开始 | 立即亮浮层 + spawn `say` | 同 |
| 时长掌握 | **估算**：字数 ÷ 4.9 字/秒 + 2.8s 固定开销 | **真实**：`didStart`/`didFinish` 回调 |
| 逐句高亮 | 估算时间轴驱动（误差 ±10%） | **真实进度** `willSpeakRangeOfSpeechString` |
| 首响延迟 | **≈2.8s**（实测：与文本长度无关的固定开销） | 常驻进程 → 百毫秒级 |
| 打断 | kill 进程（立刻停声） | `stopSpeaking(.immediate)` + 回调 |
| 语速 | `-r` 有限可控 | `AVSpeechUtterance.rate` |

> **实测数据（2026-10-16 本机，三条）**：`say -o` 合成 5 / 12 / 42 字耗时 **2.79 / 2.71 / 2.93s**
> （**与字数无关 → 固定启动开销 ≈2.8s**）；对应音频时长 0.82 / 2.25 / 8.20s → 中文语速 **≈4.9 字/秒**；
> 直接朗读 5 字总耗时 3.66s（≈0.82s 音频 + 2.8s 开销）。
>
> **这组数字直接否决两条路线**：① 「逐句各起一个 `say`」——句间会各卡 2.8s，比句子本身还长；
> ② 「整段预合成再播」——首响 = 合成 2.8s + 播放时长，延迟翻倍。
> ⇒ **同步精度真要上去只能走侧车**（`ocr_tool.swift` 同款模式），而不是继续在 `say` 上想办法。

### 6.5 与静默/勿扰的关系

`silent` 或处于勿扰时段 → **只摘掉同单元里的语音，浮层照旧**（不是整条丢弃）。
理由：用户关掉声音不等于不想看一眼。

## 8. 版本与兼容

| 规则 | 内容 |
| :--- | :--- |
| 只增不改 | 协议演进**只加字段、加 kind、加出口**；不删字段、不改已有字段语义 |
| 未知即降级 | 未知 `kind` → `card`；未知 `priority`/`life` → 默认值；未知出口 → 忽略并记 `issues`（**已有**，是协议级容错） |
| 版本号 | 宿主读 `v`；`v > 1` 时按 v1 解析并把原始 `v` 带进回执（**不抛错**） |

**三项契约测试**（防"声明了但没实现"）：
1. **降级不变量**：任意 `kind × surface`，`degradeForSurface` 结果必须是该出口原生支持的（✅ 已有）；
2. **注册表一致性**：JS 表与 Rust 表必须一致（新增，源码级比对）；
3. **渲染器覆盖**：每个出口的表里声明的 kind，其渲染器必须真的能画（否则就是"声明支持、实际空白"——这个坑矩阵里已经栽过一次）。

## 11. 明确不做（v1）

- ❌ `actions` 按钮字段（没有可点的出口，先不加）；
- ❌ HUD 局部可点（当前全局穿透；"热键切交互态"是另一条路，单独立项）；
- ❌ 协议承载二进制（图片/音频走既有产物与文件路径，IR 只放 `refs`）；
- ❌ 引入任何新依赖（前端不加库、Rust 不加 crate）；
- ❌ 让模型决定"要不要打扰用户"（决策一律在宿主，模型只能给 `priority`/`life` 建议）；
- ❌ **逐字（卡拉 OK）高亮**：v1 只到**句子粒度**；逐字要侧车的真实进度回调，排在 P-A7 之后；
- ❌ **多条语音叠念**：语音永远串行（队列上限 3）；
- ❌ TTS 换模型（Kokoro/Matcha 等）：先把**同步与打断**做对，音质另议；
- ❌ 浮层/通知里做交互式控件（与第 1 条同因）。
