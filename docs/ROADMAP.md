## 1. 产品定位

**道生一**是一个本地优先的 AI Agent 桌面客户端（Tauri 2 + Vue 3 + Rust），核心理念：

- **本地优先**：数据、密钥、记忆都存储在本机，API Key 加密落盘
- **国产模型**：深度绑定 DeepSeek，不依赖国外模型
- **Agent 化**：从「聊天工具」进化为「能干活的生产力代理」

对标 Codex 的愿景：**让道生一成为桌面端的 Codex** —— 不只是对话，而是能理解代码库、执行命令、编辑文件、跑测试、操作浏览器的自主代理。

### 已知短板（对标 Codex 的差距）

1. **不能执行终端命令**（Codex 核心能力）
2. **不能读写项目文件**（多文件编辑）
3. **不能跑测试、lint、修复错误**（验证循环）
4. **不能操作 Git**（提交/推送/分支）
5. **不能浏览网页交互**（填表单、点击，而非仅抓取）
6. **不能作为 MCP 服务器**（把自身能力暴露给 Claude Desktop 等）
7. **任务规划弱**（仅单轮 ReAct，无 Plan/子任务分解）
8. **无权限与审计**（工具调用无确认、无日志）

### 近期渲染与 UI 质量进展（2026-08-29~30）

在「回答渲染质量」与「界面一致性」上对标主流 AI 客户端（Codex / Hermes Agent / Cherry Studio）收窄差距：

- **表格竖线渲染修复**：公式 `$|G|$` 内的 `|` 不再切碎 Markdown 表格（`$` 内转 `\vert`、`$` 外绝对值转 `\|`），并加系统提示引导模型避免在表格里写字面 `|`
- **货币 `$` 转义**：`$5`/`$100` 不再误判为公式（借鉴 Hermes Agent `normalizeProseMath`）
- **KaTeX 渲染缓存**：流式渲染公式只重渲染变化项（借鉴 Hermes Agent `katex-memo`）
- **工具路由容错**：`puppeteer_*` 等 MCP 工具即使模型填错 server 也能自动路由并激活连接
- **UI 统一**：设置面板所有下拉框统一（自定义箭头 + 主题变量）、停止按钮改线性图标

## 4. 分阶段规划

### Phase 2：Agent 工具生态（近期，1-2 周）

**目标**：让道生一拥有「手和脚」——能操作本机、能对外交互。

#### 2.1 MCP 服务器集成 ⭐（接续已搁置计划）

应用从「纯客户端」升级为「客户端 + 服务端」，统一管理：

- **Rust 端**：实现 stdio MCP server，`--mcp-server` 命令行参数启动
- **暴露工具**：
  - `memory_search(query)` — 记忆检索
  - `memory_save(fact, type)` — 保存记忆
  - `web_search(query)` — 联网搜索
  - `fetch_page(url)` — 网页抓取
  - `search_conversations(query)` — 搜索对话历史
- **复用**：`mcp.rs` 的 JSON-RPC 类型；`db.rs`/`search.rs` 的既有能力
- **前端**：McpSettings 增加「服务端」Tab，展示可暴露工具 + Claude Desktop 接入配置说明

#### 2.2 终端命令执行

- 启用已安装的 `tauri-plugin-shell`
- 沙箱执行命令，输出流式回显到聊天界面
- **安全**：危险命令（rm -rf、sudo）需用户确认；可配置白名单目录
- 支持长驻进程（dev server、watch）与一次性命令

#### 2.3 文件系统操作

- 内置工具（或复用 filesystem MCP）：读写、列表、搜索文件
- 项目文件树浏览面板
- 文件内容 diff 预览

#### 2.4 联网搜索完善

- 多引擎回退：Brave → Bing → 其他
- 搜索结果缓存（避免重复请求）
- 可选的搜索 API Key 配置（用户自备）

#### 2.5 浏览器自动化

- 通过 Puppeteer MCP 提供点击/输入/截图能力
- 优先用 MCP 而非自建（避免重复造轮子）

### Phase 3：编程代理核心（中期，2-4 周）

**目标**：对标 Codex 的编程能力——理解代码库、编辑多文件、跑测试修复。

#### 3.1 代码库索引与理解

- 项目结构解析（文件树 + 依赖图）
- **语义索引**：Rust 端 embedding 或本地轻量索引，支持「自然语言找代码」
- 符号跳转（函数/类/变量定义与引用）
- 大文件分块阅读（chunking + 摘要）

#### 3.2 多文件编辑

- 代码生成 + **diff 预览**（应用内查看改动，确认后应用）
- 精确编辑原语：`replace_string`、`insert`、`create_file`、`delete`
- 跨文件重构（重命名符号、提取函数）
- 编辑后自动高亮受影响区域

#### 3.3 任务规划增强（Plan 模式）

- 复杂任务自动分解为子任务（todo list）
- 子任务进度追踪与失败重试
- 与 ReAct 循环结合：Plan → Act → Observe → 修正

#### 3.4 验证循环

- 自动运行测试（cargo test / npm test / pytest 等，按项目类型识别）
- lint 检查与自动修复
- 错误信息收集 → 回灌给模型 → 迭代修复
- 「编译通过才算完成」的门禁机制

#### 3.5 Git 集成

- 提交/推送/拉取（经 Rust 端 git2 或 shell）
- diff 查看与暂存选择
- 分支管理与合并

#### 3.6 记忆系统增强

- 向量检索：DeepSeek 无 embedding 端点，需自建本地 embedding（如 sentence-transformers via Rust ONNX 或轻量中文模型）
- 跨会话记忆聚合与遗忘策略

### Phase 4：安全与权限（贯穿各阶段，独立完善）

**目标**：代理能干活，但每一步都可控、可追溯。

#### 4.1 权限系统

- 工具级权限矩阵（每个 MCP 工具/内置工具可独立开关）
- 敏感操作用户确认（终端命令、文件删除、网络请求）
- 路径白名单（限制文件操作范围）
- 会话级权限记忆（「本次会话允许」）

#### 4.2 沙箱

- 文件沙箱：读写范围限制
- 网络沙箱：域名白名单
- 命令沙箱：禁止 sudo/危险命令

#### 4.3 审计日志

- 工具调用全记录（参数、结果、耗时、token）
- 操作回放与导出
- 会话内「撤销最近操作」

#### 4.4 子代理

- 并行子代理处理独立子任务（搜索、编辑、测试并行）
- 主代理汇总结果
- 借鉴 Codex 的 multi-agent 协作模式

#### 4.5 外部编码 Agent 退役路线（2026-08-26 决策）

> 背景：道生一已具备内置编码能力（P-A1 Git / P-A2 验证循环 / P-A3 代码库理解 / P-A4 多文件编辑+diff / P-A5 任务规划）。外部编码 Agent（Claude Code / Codex）委派是过渡方案，终局是**零外部编码依赖、多 agent 协作内置化**。

- **阶段一（当前）**：外部委派降级为隐藏兜底——从设置面板移出（不再是一等公民），保留 `delegate_coding_agent` 内置工具由 agent 按需调用，提示词标注「外部兜底，仅当内置编码能力不足时用」
- **阶段二（研发重心）**：内置多 agent 协作——子代理获得工具能力（能调 git/编辑/测试/搜索）、支持并行执行、角色分工（规划/执行/验证/评审）、主代理汇总仲裁
- **阶段三（多 agent 成熟后）**：彻底移除外部委派代码，实现零外部编码依赖

## 6. 技术选型建议

| 能力 | 选型 | 理由 |
|------|------|------|
| MCP 服务器 | Rust 原生实现（复用 mcp.rs 类型） | 零新依赖，本地优先 |
| 终端执行 | tauri-plugin-shell（已装） | 官方方案 |
| 本地 embedding | ONNX Runtime + 轻量中文模型 | 不依赖外部 API |
| 代码语义搜索 | tantivy（Rust 全文）或 sqlite FTS5 | 轻量本地 |
| Git 操作 | git2 crate（Rust） | 避免 shell 注入 |
| 子代理 | tokio 任务 + 主从消息总线 | 复用现有 Rust 异步栈 |
