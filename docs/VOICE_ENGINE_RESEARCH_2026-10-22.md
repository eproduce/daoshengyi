# 中文 TTS 方案调研报告（2025–2026）

> **实测环境**：本机 `macOS 26.7.2 (25G330)`、`x86_64`、`Intel i7-9750H`、16 GB、无 GPU。
> 报告里的「**实测**」= 我在本机跑出来的数字；「**查证**」= 官方文档/仓库原文；「**推测/社区经验**」= 无一手来源的判断，已单独标注。

## 1. Apple 系统音色（macOS 26, zh_CN / zh_TW）

### 1.1 现状：有 Premium 档，中文共 3 个可下载资产

**实测** `say -v '?'` 本机共 180 个音色，中文 19 条：

| 音色 | Locale | 备注 |
|---|---|---|
| Tingting 婷婷 | zh_CN | 经典音色（本机为 compact） |
| Eddy / Flo / Grandma / Grandpa / Reed / Rocko / Sandy / Shelley | zh_CN + zh_TW | macOS 26 新增的 8 个具名音色，中英双语各一份 |
| Meijia 美佳 | zh_TW | |
| Sinji 善怡 | zh_HK | |

**查证**（直接读系统资产目录 XML）：

- `/System/Library/AssetsV2/com_apple_MobileAsset_VoiceServicesVocalizerVoice/com_apple_MobileAsset_VoiceServicesVocalizerVoice.xml` → 40 个资产，**中文只有 3 条，且全部是 `.premium` 后缀**：
  - `com.apple.speech.synthesis.voice.tingting.premium`，zh-CN，解压后 **625.0 MB**
  - `com.apple.speech.synthesis.voice.meijia.premium`，zh-TW，**664.6 MB**
  - `com.apple.speech.synthesis.voice.sinji.premium`，zh-HK，**325.8 MB**
- `/System/Library/AssetsV2/com_apple_MobileAsset_MacinTalkVoiceAssets/...xml`（22 个资产）→ **无中文**。
- `/System/Library/AssetsV2/com_apple_MobileAsset_VoiceServices_GryphonVoice/...xml`（214 个）→ 中文 Siri 系音色：`yushu`(女, zh-CN, 472 MB)、`limu`(男, zh-CN, 437.9 MB)，另有 `neural` 类型的 `linfei / shufen / chenghan` 等（≈500 MB 级）。**本机已装了 `yu-shu`**（`…/748b7f65….asset`，532 MB，内含 `uselect_yu-shu_full.dat`），但 `say -v '?'` **不列出**它 —— Siri 音色对 `say` 不开放。

> 结论：**macOS 26 中文确实有 Premium 可下载音色（Tingting / Meijia / Sinji），但本机三类音色目录里没有单独的 "Enhanced" 中文条目**（macOS 15 时代常见 Enhanced+Premium 两档）。这一点只对我读到的这些资产目录成立，最终以「系统设置 → 辅助功能 → 朗读内容 → 系统声音 → 管理声音」实际列表为准。

### 1.2 音质提升多少？

- **查证**：Apple 的公开 API 把音色质量分三档 `AVSpeechSynthesisVoiceQuality` = `default / enhanced / premium`（[Apple 文档](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisvoicequality)）。Premium 是神经网络音色。
- **查证（间接量化）**：compact 音色只有几 MB；Tingting Premium 解压 **625 MB**（约 100 倍），Meijia Premium 665 MB。这符合"神经声码器 + 大模型"的体积特征。
- **推测**：Apple 不发布 MOS，社区普遍认为 Premium 相对 compact 是"质变"（韵律、连读、气息自然），大致接近 Azure 标准神经音色的水平；但**没有可引用的客观数据**，建议以你自己的 A/B 试听为准。
- **实测（compact）**：Tingting 输出 **22.05 kHz / 16-bit PCM**；`say` 命令行**每次进程启动固定 ~2.0–2.3 s**（7 字短句 2.12/1.98/2.31 s），但合成本身很快（17.5 s 音频总耗时仅 2.15 s）。也就是说，你现在的"机械感"里还混着 ~2 s 的固定启动延迟 —— 改成常驻进程（`AVSpeechSynthesizer`）能直接省掉。

### 1.3 检测安装状态（可脚本化，已实测）

**实测坑**：`say -v "根本不存在的音色"` 仍然 **exit code 0**，并回退到默认音色输出音频。**不能靠退出码判断**。

三种可行检测：

1. 解析 `say -v '?'`（最简单）：已安装音色会带 `(Enhanced)` / `(Premium)` 后缀。
2. 检查资产目录：`/System/Library/AssetsV2/com_apple_MobileAsset_VoiceServicesVocalizerVoice/*.xml`（可 `plutil` 解析）。
3. **程序化查询（推荐，已实测可用）**：私有 `MobileAsset.framework` 的 `MAAssetQuery`，本机返回 40 条资产并给出 state：

```
vid=com.apple.speech.synthesis.voice.tingting.premium name=ting-ting state=1
```
（`state=1` = 未下载；本机 3 个中文 premium 全是 1。）

`MAAsset` 可用的方法（`class_copyMethodList` dump 得到，macOS 26）：`-state -refreshState -getLocalFileUrl -startDownload: -startDownload:then: -purgeSync`。

### 1.4 能否用脚本触发下载？

- **查证**：Apple 只文档化了 UI 路径（[支持文档](https://support.apple.com/guide/mac-help/change-the-voice-or-language-mchlp2290/mac)：系统设置 → 朗读内容 → 系统声音 → 管理声音 → 勾选，联网自动下载）。
- **实测**：没有公开 CLI（`say` 无下载子命令，`assetutil` 只能读）。
- **可行但未验证**：用 `MAAsset.startDownload:then:` 对上面 3 个 asset 发起下载（方法确实存在，但我没有真的去拉 625 MB，属于**未实测**）。需要签名 App 里调用私有框架，App Store 上架会因此被拒。
- 折中方案：**首次启动检测 state，若为 1 就弹一句"请到系统设置下载 Tingting Premium（625 MB，一次性）"，并给出深链接** `x-apple.systempreferences:com.apple.preference.universalaccess?SpeakableItems`。

## 2. 免费在线：edge-tts

### 2.1 可用性与音色（实测，2026-10-22）

**实测**：`edge-tts 7.3.1` 当前**可用**。直接拉官方 voices 接口：**322 个音色，中文 14 个**：

| 音色 | 性别 | 定位 |
|---|---|---|

| `zh-CN-XiaoyiNeural` | 女 | Cartoon/Novel，Lively |
| `zh-CN-YunxiNeural` | 男 | Novel，Lively/Sunshine |
| `zh-CN-YunjianNeural` | 男 | Sports，Passion |
| `zh-CN-YunyangNeural` | 男 | News，Professional |
| `zh-CN-YunxiaNeural` | 男 | Cartoon，Cute |
| `zh-CN-liaoning-XiaobeiNeural` | 女 | 东北话 |
| `zh-CN-shaanxi-XiaoniNeural` | 女 | 陕西话 |
| `zh-TW-HsiaoChenNeural` / `HsiaoYuNeural` / `YunJheNeural` | — | 台湾 |
| `zh-HK-HiuGaaiNeural` / `HiuMaanNeural` / `WanLungNeural` | — | 粤语 |

### 2.2 参数支持

- **支持**：`--rate` / `--volume` / `--pitch`（`--rate=-50%`、`--pitch=-50Hz` 写法），`--voice`、`--write-subtitles`（字幕/SRT）。
- **不支持**：**自定义 SSML**。README 原文："Support for custom SSML was removed because Microsoft prevents the use of any SSML that could not be generated by Microsoft Edge itself… the service only permits a single `<voice>` tag with a single `<prosody>` tag inside it."（[rany2/edge-tts README](https://github.com/rany2/edge-tts)）
- **不支持** `mstts:express-as` / style / role —— 只能靠 `rate/pitch` 微调。

### 2.3 延迟（实测，本机直连）

| 场景 | 首包 | 总耗时 | 备注 |
|---|---|---|---|
| 冷启动首句（7 字） | 1385 ms | 2835 ms | 含 TLS/WebSocket 握手 |
| 热连接第 2/3 句 | 548 / 349 ms | 799 / 476 ms | 连接复用后 |
| 78 字长句 | 668 ms | 1049–1572 ms | 音频 16.2 s → **RTF 0.06–0.10** |

> 结论：**热连接首包 0.35–0.7 s**，长文本吞吐极快。对你的 Agent 场景（短句播报）体感 ≈ 0.5 s，比现在的 `say`（~2 s）好。

### 2.4 许可与合规风险（重要）

- **查证（许可）**：`edge-tts` 代码 **LGPLv3**（`LICENSE`："The MIT license is used for `src/edge_tts/srt_composer.py` only. All remaining files are licensed under the LGPLv3."）。LGPL 对"独立进程调用"较友好，但你要分发就得能替换该库。
- **查证（非官方的事实证据）**：`src/edge_tts/constants.py` 里写死了 **消费级朗读端点 + 固定 token + Edge 浏览器伪装**：
  ```
  BASE_URL = "speech.platform.bing.com/consumer/speech/synthesize/readaloud"
  TRUSTED_CLIENT_TOKEN = "6A5AA1D4EAFF4E9FB37E23D68491D6F4"
  Chromium/143 UA, Origin: chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold
  ```
  并有 `Sec-MS-GEC` 反爬签名（`communicating.py`）。
- **结论（明确判断）**：**这不是官方 API**，是逆向 Edge「大声朗读」的私有接口。风险：①随时可能加验证/封 IP（历史上多次 403）；②微软服务条款未授权第三方使用；③商业产品里默认使用有法务与稳定性双重风险。**建议做成"可选后端 + 本地缓存 + 失败自动回退"**，不要做唯一 TTS。

## 4. 本地离线（CPU 可跑）—— 本机实测数据

我在本机用 `sherpa-onnx 1.13.8`（有 `macosx_10_15_x86_64` wheel）+ 官方模型，直接量了 RTF（合成耗时 ÷ 音频时长）与首句耗时：

| 模型 | 体积 | 采样率 | RTF（6线程） | 7字句首响 | 27字句 | 许可 |
|---|---|---|---|---|---|---|
| **matcha-icefall-zh-baker** | 95 MB（含 hifigan 3.6 MB） | 22.05 kHz | **0.06** | **161 ms** | 310 ms | ⚠️ 数据集**非商用** |
| **piper zh_CN-huayan-medium** | 79 MB | 22.05 kHz | **0.05** | **58 ms** | 249 ms | ⚠️ MODEL_CARD 写 "License: Unknown" |
| **MeloTTS zh_en (vits-melo)** | 197 MB（fp32） | **44.1 kHz** | **0.25** | 186 ms | 615 ms | ✅ MIT |
| vits-icefall-zh-aishell3 | 209 MB | 8 kHz | 0.03 | 70 ms | 156 ms | 音质太差，仅作速度基线 |
| **Kokoro int8 multi-lang v1.1** | 210 MB | 24 kHz | **1.70** ❌ | **3012 ms** | 10.4 s | ✅ Apache-2.0 |
| **Kokoro fp32 multi-lang v1.1** | 311 MB | 24 kHz | **0.52–0.65** | 981–1107 ms | 3.2–3.5 s | ✅ Apache-2.0 |

**反直觉但重要的发现**：**Kokoro 的 int8 量化在 x86 上比 fp32 慢 3 倍**（RTF 1.70 vs 0.52–0.57）。原因是 sherpa-onnx 的 int8 算子在 Intel 上走反量化路径，没有 VNNI 加速。**Intel Mac 上必须用 fp32**。

### 4.1 官方 RTF 参照（Raspberry Pi 4，4×A72 —— 比 i7-9750H 弱很多）

sherpa-onnx 官方表（[RTF of pre-trained models](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/rtf.html)）：

| 模型 | 1 线程 | 2 | 3 | 4 | 体积 |
|---|---|---|---|---|---|
| matcha-icefall-zh-baker | 0.892 | 0.536 | 0.432 | **0.391** | 73 MB |
| kokoro-multi-lang-v1_1 | 7.635 | 4.470 | 3.430 | **3.191** | 311 MB |
| vits-melo-tts-zh_en | 6.727 | 3.877 | 2.914 | **2.518** | 163 MB |
| aishell3 | 0.365 | 0.220 | 0.171 | **0.156** | 30 MB |

> 与我的实测一致：i7-9750H 单核约等于 Pi4 的 5–7 倍。**Kokoro 在这台机器上就是"基本不能流式"**（1 秒音频要 0.5–1.7 秒算）。

### 4.2 Kokoro-82M 细节

- **查证**：82M 参数，StyleTTS2 + ISTFTNet，**Apache-2.0**（[hexgrad/Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)）。
- **中文版**：`hexgrad/Kokoro-82M-v1.1-zh`，**100 个中文说话人**，训练数据 >100 h（龙猫数据），2025-02-26 发布，103 voices / 2 langs（[模型卡](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)）。
- **ONNX 体积**（[onnx-community/Kokoro-82M-v1.1-zh-ONNX](https://huggingface.co/onnx-community/Kokoro-82M-v1.1-zh-ONNX)）：`model.onnx` 339.4 MB / `fp16` 163.6 MB / `int8` 127.4 MB / 每个 voice `.bin` 0.5 MB。
- **G2P 依赖**：Python 侧需 `misaki[zh]`（jieba + pypinyin + ordered-set）；sherpa-onnx 侧自带 `dict/ + lexicon-zh.txt + espeak-ng-data`，无需 Python。
- **许可提醒**：v1.1-zh 数据由 LongMaoData "免费无偿提供"，权重 Apache-2.0；`kokoro` 仓库 9,585★。

### 4.3 sherpa-onnx 工程可用性（对 Tauri 很关键）

- **查证**：v1.13.8 release 提供 **macOS x86_64 预编译**：`sherpa-onnx-v1.13.8-osx-x64-static.tar.bz2`（286.4 MB）、`-shared`（22.8 MB）、`-shared-lib`（10.0 MB）、`-static-lib`（20.6 MB），另有 `osx-universal2-*`（可一份打 Intel+ARM）（[releases](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.8)）。
- **Rust API**：官方文档有 Rust 章节；社区 crate **`sherpa-rs 0.6.8`**（2025-10-05，97,639 下载，[thewh1teagle/sherpa-rs](https://github.com/thewh1teagle/sherpa-rs)）。
- **Tauri 支持**：官方有 "Tauri Desktop Apps" 文档与 `tauri-examples/`，但**示例只覆盖 ASR**（[文档](https://k2-fsa.github.io/sherpa/onnx/tauri/index.html)）→ TTS 需要自己写 sidecar/FFI。
- **备选 Rust 路线**：`ort 2.0.0-rc.15`（23M 下载）+ 直接用 Kokoro ONNX；或 crate `kokoro-tts 0.3.3`。

### 4.4 许可风险（做产品必须先看）

| 模型 | 许可 | 风险 |
|---|---|---|
| Kokoro v1.1-zh | Apache-2.0 | 低 |

## 5. 本地克隆 / 高自然度（需 GPU）

| 系统 | 参数 | 官方速度 | CPU 可行性 |
|---|---|---|---|
| **CosyVoice 2 / 3** | 0.5B（CosyVoice3-0.5B-2512，2025-12 发布） | **流式延迟 150 ms**（官方宣称，需 GPU）；9 语言 + 18 方言 | ❌ 需要 GPU；CPU 上推测 ≥ 10× 实时 |
| **IndexTTS-2.5** | 0.8B | **RTX 4090：RTF 0.207（bf16）/ 0.206（fp32 2.5）**；2.0 为 0.326–0.375；7 字句 RTF 0.287 | ❌ 4090 上才 0.2，CPU 推测 20–50× 实时 |
| **F5-TTS** | Base | **L20：PyTorch 0.1467 / TensorRT-LLM 0.0402**（16 NFE） | ❌ CPU 不可行（推测 >5× 实时） |
| **GPT-SoVITS v2ProPlus** | ~几百 M | **4060Ti 0.028；M4 CPU 0.526**（README 原文） | ⚠️ **唯一 CPU 勉强可跑**；i7-9750H 估计 RTF 1.5–3（慢于实时） |
| **Spark-TTS** | 0.5B | **L20：RTF 0.1362（并发1）/ 0.0737（并发2），平均延迟 876 ms** | ❌ 需 GPU |

**结论**：这一类在这台机器上**全部不实用**（连 GPT-SoVITS 的 CPU 模式都是"慢于实时"）。它们只在有 GPU 的服务器/云端才有意义；若想要"克隆音色 + 情感控制"，走云端（CosyVoice / MiniMax / ElevenLabs）比本地更现实。

## 6. 客观可查的评测

### 6.1 seed-tts-eval（事实标准）

**查证**（[BytedanceSpeech/seed-tts-eval](https://github.com/BytedanceSpeech/seed-tts-eval)，1,607★）：
- 测试集：EN 1,000 条（Common Voice）、**ZH 2,000 条（DiDiSpeech-2）**，另有 ZH hardcase。

### 6.3 缺口（必须说明）

## 7. 排序建议（这台无 GPU 的 Intel Mac）

### 🥇 第 1 选：Apple **Tingting Premium** + 常驻 `AVSpeechSynthesizer`

- **自然度**：对现在的 compact 是质变（推测，建议 A/B）—— 但零成本、零依赖。
- **联网依赖**：仅**一次性**下载 625 MB；之后完全离线。
- **安装成本**：0（系统自带），下载需用户点一次（或私有 MobileAsset API 自动拉，未实测）。
- **延迟量级**：常驻进程 + `write(_:toBufferCallback:)`（macOS 10.15+，[文档](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/write(_:tobuffercallback:))）可拿 PCM 流，首句 ~100–300 ms（首次加载语音包会慢），**彻底干掉现在 `say` 的 ~2 s 进程启动**。
- **风险**：①用户不下载就仍用 compact；②`say`/AVSpeech 的韵律控制弱（无 style）；③Siri 音色（Yu-shu/Li-mu）对 `say` 不开放。

### 🥈 第 2 选：**Azure Speech `zh-CN-XiaoxiaoNeural`（+ `mstts:express-as` style）**

- **自然度**：商用云里中文第一梯队，20 种 style（`chat` / `chat-casual` / `assistant` 非常适合 Agent），还可上 DragonHD。
- **联网依赖**：强（必须联网 + API key）。
- **安装成本**：SDK/REST 接入半天；密钥与配额管理。
- **延迟量级**：同区域 ~200–400 ms 首包（推测），流式可边生成边播。
- **成本**：**$15/百万字符** ≈ 每万汉字 ¥0.11 —— 按你日均 1 万字算，每月 ¥3 量级，可忽略。
- **风险**：跨境网络抖动；F0 免费层 20 次/60 s 太低；数据出境合规。

### 🥉 第 3 选：**MeloTTS（sherpa-onnx 进程内，MIT）**

- **自然度**：中等偏好（明显好于 Piper/Matcha 的"播音腔"），但达不到云服务水平。
- **联网依赖**：**零**。
- **安装成本**：模型 197 MB 打进 App；Rust 用 `sherpa-rs` 或 sidecar（`osx-x64-shared` 22.8 MB）。
- **延迟量级**：**实测 RTF 0.25，44.1 kHz**，27 字句 615 ms，7 字句 186 ms → 按句切分流式播报体感 <0.3 s。
- **风险**：44.1 kHz 输出需要重采样；情感/风格不可控；长句韵律一般。

### 备选（按场景）

- **要"最像人"且能接受合规风险** → `edge-tts`（Xiaoxiao）：免费、热连接首包 0.35–0.7 s、RTF 0.06，但**非官方接口**，必须做降级链。
- **要"极致快 + 全离线"** → `matcha-icefall-zh-baker`（RTF 0.06，161 ms），**但数据集仅限非商用**；商用换 `vits-zh-hf-fanchen-C`（187 说话人）。
- **别用** → Kokoro 在这台机器上（fp32 RTF 0.52，int8 1.70）达不到对话级延迟；int8 尤其要避开。
- **别用** → 所有本地克隆模型（CosyVoice2/3、IndexTTS、F5、Spark、GPT-SoVITS）在此硬件上不可行。

### 推荐落地架构

```
TTS 路由（按优先级 + 失败回退 + 本地缓存）
  1) 本地 Apple Premium（AVSpeechSynthesizer, 离线, 零成本）
  2) 本地 MeloTTS/sherpa-onnx（离线兜底，MIT）
  3) Azure Xiaoxiao + style（联网增强，用于"重要播报"）
  ✗ edge-tts 仅作为可选实验开关（合规风险）
```
关键工程点：**按句切分 + 边合成边播**（首句 <300 ms 即可），以及**不要用 `say` 的退出码判断成败**（实测恒为 0）。
