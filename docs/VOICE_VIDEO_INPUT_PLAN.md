> 明确不做 ort-sys 系 / whisper.cpp Metal / Apple SFSpeech 离线中文）。
> 本文补两块：**① 按 DSH `voice-input` 子系统借鉴来的交互与生命周期设计；② 视频/视觉输入方案（YOLO × 本地视觉）**。

## 一、语音输入：借 DSH 的三条设计（我们缺的正是这部分）

DSH 的 `voice-input` 子系统（`docs/subsystems/voice-input.zh.md`）把语音识别拆成「服务定义 / Provider / 消费者」，
并且**不把语音当成特殊通道**。三条最值得抄的做法：

| DSH 做法 | 为什么重要 | 我们怎么用 |
| --- | --- | --- |
| **转写不写会话**：识别结果先进**输入草稿**，只有用户提交才成为「模型可见文字」 | 误识别不会直接触发 agent 跑一轮（省 token、避免误操作） | 转写 → 填进 `ChatInput` 草稿 → 用户回车/点发送才发 |
| **准备（preparation）是独立生命周期**：模型下载/校验/加载有分步状态与进度，取消/失败后**保留状态**，已校验文件重试与空闲回收后**继续复用** | 首次要下几十~几百 MB 模型，静默等待会被当成卡死 | 设置里给「语音」块：准备步骤列表（下载→校验→加载）、字节进度、失败分类（网络/校验/磁盘）+ 重试 |
| **本地 Provider 串行执行 + 队列上限 + 进程独立回收** | 语音推理与 LLM 抢 CPU，会互相拖慢（本机 6 核无 GPU） | 识别并发=1；空闲 N 分钟释放模型内存（照本地运行时的 `IDLE_KILL_SECS` 模式） |

**阶段 1（最小闭环，建议先做）**

> **前置条件（本次实测）**：本机**没有** `~/.cargo/config.toml`（走默认源），而官方 `index.crates.io` **不可达（HTTP 000）**
> —— 现有依赖能编译是因为早已进了本地缓存（cache 142M / src 949M）。**所以新增任何 Rust 依赖前，必须先配稀疏镜像**：
> `rsproxy.cn`、`mirrors.tuna.tsinghua.edu.cn`、`mirrors.ustc.edu.cn` 三者的 sparse index 实测均 **200**，
> 且 `sherpa-onnx` 在索引中确实存在。另外该 crate 在构建时会去 GitHub Releases 取预编译原生库（GitHub 在本机可达 ✅）。

- Rust 新增 `voice` 模块：`cpal` 采 16kHz 单声道 → `sherpa-onnx` 的 Silero VAD → 中文模型识别（草稿档）
- 前端：输入栏麦克风按钮 + **按住说话**（复用已装的 `tauri-plugin-global-shortcut` 做全局热键）；
  录音中显示**实测麦克风音量波形**（DSH 也这么做：波形来自真实音量而非假动画）；Esc / 切走页面 → 丢弃
- 识别完成 → 插入草稿（可撤销的一次文本插入）；**不自动发送**
- 权限：麦克风用途说明写进 `Info.plist`（打包版才生效）

**阶段 2/3**（详见既有调研 §六）：实时草稿 + 精修、TTS（macOS `say`/`AVSpeechSynthesizer`，已内置 9 个中文音色）→ 打断与唤醒词。
**明确不做**：把音频默认送云端（违背本地优先）。

## 二、视频/视觉输入：三层栈，把「确定性」放在最前面

关键前提（都是实测过的本机事实）：CPU-only（无可用 GPU）、本地 VLM 只有 `llava-phi3` 3.8B（**9.9 tok/s，输出属"幻觉级"**）、
`image_inspect` 已能算确定性像素/几何、`ocr_tool.swift`（Vision）已就位、**Rust 侧 ONNX Runtime 在本机不可构建**
（`ort-sys` 无 `x86_64-apple-darwin` 预编译，2026-09-11 实测）。

因此视觉不该「整帧喂大模型」，而应分三层，**能不用模型就不用模型**：

| 层 | 能力 | 成本 | 现状 |
| --- | --- | --- | --- |
| **① 确定性像素/几何** | 字符切分、封闭空洞、字形点阵（编号/票据位数核验） | 微秒级 | ✅ 已有 `image_inspect` |
| **② macOS Vision 原生**（零模型下载） | `VNClassifyImageRequest`（Apple 内置图像分类，千级类别）、`VNRecognizeAnimals`、人脸/人体/人体姿势、条码、`VNRecognizeText`（OCR）、`VNGenerateImageFeaturePrint`（帧间相似度） | 毫秒~百毫秒 | 🟡 只有 OCR（`ocr_tool`）——**扩展同一侧车即可** |
| **③ 本地 VLM**（llava-phi3 / llama.cpp） | 「看图说话」、开放性描述 | **10~40s/帧**、会幻觉 | ✅ 已有（18080 端口按需起停） |
| **④ YOLO（可选）** | 多目标**检测框 + 计数**（COCO 80 类） | CoreML 推理，快；但需一次性转换 | ❌ 未做 |

### YOLO 与本地视觉模型的正确结合方式（用户的想法是对的）

不要「YOLO 判完丢给 VLM 再说一遍」，而是**分工：检测做 grounding，VLM 做局部理解**：

```
帧 ──► ②/④ 检测/分类 ──► 有目标？在哪？（框/类别/计数 —— 确定性、可复算）
                        └─► 按框裁剪 + 放大 ──► ③ VLM 只看这一小块（描述文字/状态/关系）
                                              └─► ① 需要精确数字时再走 image_inspect
```

好处：① VLM 输入变小 → 更快更准、幻觉显著下降（它常把整图细节编出来）；② 「有几个人/有没有条码/什么类别」
这类问题**完全不需要 VLM**（省 10~40s/帧）；③ 结论可复算（检测层是确定的）。

**YOLO 的落地路径（受本机约束）**：❌ 不走 Rust ONNX（不可构建）；✅ 走 **CoreML（`.mlpackage`）+ Swift 侧车**
（与 `ocr_tool.swift` 同一模式）：模型转换（`ultralytics` → `coremltools`）需一次性 Python 环境，产出 `.mlpackage`
随包分发；推理在 Swift 侧 + Vision/CoreML。
**建议先做 ②**：`VNClassifyImageRequest` + 人脸/人体/条码这套零下载能力，能覆盖大部分"分类/有没有"的问题；
**只有确实需要「框 + 计数」时再上 YOLO**（转换成本 vs 收益要算清楚）。

### 视频输入：抽帧 → 选关键帧 → 走上面同一套

```
视频 ──► AVFoundation 抽帧（Swift 侧车，与 ocr_tool 同模式；或先按 N 秒均匀抽）
     ──► VNGenerateImageFeaturePrint 帧间相似度去重 ──► 只留"画面真的变了"的关键帧
     ──► 每帧走 ①+②（确定性+Vision 原生）
     ──► 只在需要"描述"时，对少量关键帧裁剪局部 → ③ VLM
     ──► 汇总成时间轴（谁/什么在第几秒出现、画面变化点）
```

**工具形态**：`video_inspect(path, question)`（本机文件）。**必须有的护栏**：
- 抽帧上限（如 ≤12 帧）+ 总耗时预算（超过就返回"已抽 N 帧、未完成"而不是静默卡住）
- 视频时长/大小上限；超限提示用户截取片段
- 明确告知模型「这是抽帧结论，不是连续观察」（避免它编造"第 3 秒他笑了"）
- 隐私：全程本机处理（符合项目「数据不出设备」理念）

## 三、建议顺序

| 优先级 | 事项 | 成本 | 依赖 |
| --- | --- | --- | --- |
| 🟢 1 | 语音阶段 1（按住说话 → 草稿，不自动发送）+ 准备状态机 | 2~3 天 | `sherpa-onnx` crate（官方 osx-x64 预编译，已验证可构建性） |
| 🟢 2 | Vision 原生视觉层扩展（分类/人脸/人体/条码/特征指纹）到 `ocr_tool` 侧车 + 新命令 `vision_inspect` | 1~2 天 | 无新依赖（系统框架） |
| 🟢 3 | 视频抽帧 + 关键帧 + 时间轴汇总（`video_inspect`） | 2~3 天 | 第 2 项 |
| 🟡 4 | VLM 局部裁剪理解（把 YOLO/Vision 的框喂给 llava-phi3） | 1~2 天 | 第 2 项 |
| 🔵 5 | YOLO（CoreML 侧车 + 一次性模型转换） | 2~4 天 + Python 环境 | 第 2 项；**先确认真的需要"检测框/计数"** |
| 🔵 6 | TTS（`say` 朗读 + 流式 + 打断） | 1~2 天 | 语音阶段 1 |

**明确不做**：Rust ONNX 系推理、整段视频/整帧大图喂 VLM、假设 GPU 加速、把音视频默认送云端。
